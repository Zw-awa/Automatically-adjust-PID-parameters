# 架构说明

本项目把实时控制留在 MCU，把数据分析、参数建议、历史记录和在线协调放在 PC。

## 总体数据流

```text
软件仿真 ─┐
CSV 文件 ─┼─> DataSample ─> 数据质量检查 ─> 性能指标 ─> 调参策略
MCU 串口 ─┘                                      │
                                                  v
历史记录 <─ 本地保存 <─ 参数限制/人工确认 <─ PID 建议
                                                  │
                                                  v
                                   协议 v2 请求 ─> MCU 周期边界生效
                                                  │
                                                  v
                                      匹配 ACK 后更新本地配置
```

仿真、离线和在线模式共享同一套数据模型与分析逻辑，区别主要是样本来源和参数是否
发送给真实设备。

## 核心模块

| 模块 | 责任 |
| --- | --- |
| `core/config.py` | 加载配置、参数范围、输出范围和本地配置保存 |
| `core/analyzer.py` | 数据质量门控与性能指标计算 |
| `core/serial_manager.py` | 协议 v2、串口线程、请求关联和 ACK/NACK 校验 |
| `core/data_collector.py` | 在线采样缓冲和采集边界 |
| `core/simulator.py` | 软件对象响应生成 |
| `core/tuner.py` | LLM 请求、结果解析和参数变化限制 |
| `core/history_manager.py` | 调参记录、趋势和振荡历史 |
| `core/workflows.py` | offline/online/simulate 流程编排 |
| `main.py` | 命令行入口和参数解析 |

`experimental_lab/` 在相同分析和调参能力之上增加会话、策略比较、SQLite 和本地服务，
不是 MCU 在线流程的必经组件。

## 三种调参模式

### simulate

`core/simulator.py` 生成统一的 `DataSample`，经过质量检查和性能分析，再进入调参。
它用于验证 PC 流程，不代表真实电机模型。

### offline

CSV 被解析成相同的 `DataSample`。分析与建议不会直接影响硬件，适合实机数据复盘和
人工确认。

### online

串口后台线程解析 MCU 遥测，主流程按时间窗口取样、分析并生成建议。参数发送前注册
ACK 队列，避免设备响应先于等待逻辑到达而丢失。

## 协议 v2 的更新时序

```text
PC                                MCU
│                                  │
├─ 注册 request_id 的 ACK 队列     │
├─ PID:req123:speed:... ─────────> │
│                                  ├─ 校验格式/范围/控制环
│                                  ├─ 暂存参数
│                                  ├─ 在控制周期边界原子应用
│ <──────── ACK:req123:speed:... ──┤
├─ 校验 request_id、loop、实际参数 │
└─ 成功后更新配置和历史             │
```

NACK、超时、旧格式 ACK、参数不一致或错误 request ID 都不能确认更新成功。

## 数据质量门控

质量检查位于调参策略之前，避免模型根据损坏数据给出建议。当前拒绝：

- 样本不足。
- NaN 或 Infinity。
- 非递增时间戳。
- 过大的采样间隔。
- `error != target - actual`。
- 非法输出范围配置。

饱和检测依赖每个控制环的 `output_limits`。单位和范围必须与 MCU 遥测一致。

## 参数安全边界

PC 端提供：

- Kp/Ki/Kd 绝对上下限。
- 单轮最大变化率。
- 过小变化吸附。
- 默认人工确认。
- ACK 关联和实际参数比对。
- 调参历史记录。

MCU 端仍必须负责：

- 最终输出限幅和抗积分饱和。
- 传感器有效性检查。
- 过流、过温、超速、堵转和急停。
- 看门狗和通信超时。
- 稳定参数回滚。

## STM32 示例分层

两套示例都采用相同概念：

```text
PID 核心       协议、PID、遥测、参数边界
配置           周期、增益、限幅、软件对象开关
平台端口       UART、时基、环形缓冲、中断/回调
用户接口       目标、实际值、执行器输出
```

标准库版通过 `stm32f10x_it.c` 转发 SysTick/USART1 中断；HAL 版通过
`pid_tuner_callbacks.c` 转发 HAL UART 回调。协议解析和浮点格式化始终在主循环，
不放进 ISR。

## 配置和历史写入

建议只有在本地限制通过后才进入应用流程。在线模式必须收到匹配 ACK；成功后才把
参数写回显式配置路径并保存历史。失败或被拒绝的建议不应伪装成已应用记录。
