# 项目工作方式说明

这份文档解释的是：当你运行这个工具时，它大概在做什么。

## 1. 这个项目负责什么

你的 MCU 负责真正的控制，这个项目负责：

1. 读取一段控制响应数据
2. 算出超调量、调节时间、稳态误差这些指标
3. 把当前 PID 和目标要求一起交给模型
4. 得到新的参数建议
5. 在在线模式下把建议发回设备

所以你可以把它理解成一个“调参助手”。

## 2. 三种模式本质上都在做同一件事

不管你运行的是仿真、离线还是在线，核心步骤都差不多：

1. 拿到一段数据
2. 分析这段数据
3. 让模型看当前表现好不好
4. 得到下一轮 PID 建议

区别只在于数据从哪里来。

### 仿真模式

数据来自软件模型。

### 离线模式

数据来自 CSV 文件。

### 在线模式

数据来自 MCU 串口。

## 3. 为什么项目会保存历史记录

因为调参不是只看当前一轮。

历史记录有两个作用：

1. 你自己可以回看之前调过什么
2. 模型下一轮也会参考最近历史，减少参数来回跳

## 4. 为什么在线模式不会直接强制改参数

因为项目默认把安全放前面。

所以在线模式会做这些事：

1. 限制单次参数变化幅度
2. 限制参数上下限
3. 默认询问你是否应用
4. 等设备返回 `ACK`

你可以把它理解成“建议先给出来，再由你决定要不要真正写进去”。

## 5. 为什么配置文件会被更新

如果新的 PID 被接受，项目会把参数写回本地配置。

这样做的好处是：

1. 下一轮会从新参数继续
2. 下次重新启动时也能接着用

## 6. 使用时最值得记住的顺序

最稳妥的使用顺序是：

1. 先本地分析
2. 再仿真
3. 再监看串口
4. 再在线调参

这样一旦出问题，你最容易知道到底是：

1. 数据问题
2. API key 问题
3. 串口问题
4. 设备问题
